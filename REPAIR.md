# Claude Code Launcher: промт для починки

> **Для человека.** Если лаунчер перестал открываться или работает странно, дважды щёлкните `Repair.cmd`.
> Откроется Claude Code в папке лаунчера, он прочитает этот файл и починит. Можно и вручную:
> скопируйте всё, что ниже линии, и вставьте в Claude Code (или в «Настройки → Скопировать промт для починки»).

---

Ты чинишь **Claude Code Launcher** на этом компьютере (Windows 10/11). Порядок: сначала разберись, что сломано, потом исправь, потом проверь, что всё работает. Отвечай пользователю на его языке (язык лаунчера записан в `settings.json`, поле `lang`). Перед удалением или перезаписью файлов говори, что собираешься сделать.

**Не трогай:** историю сессий Claude (`~/.claude/projects`), чужие настройки Claude Code (`~/.claude/settings.json`) и файлы вне перечисленных ниже мест.

## Как устроен лаунчер

| Что | Где |
| --- | --- |
| Сам лаунчер: один скрипт PowerShell 5.1 | `%LOCALAPPDATA%\ClaudeCodeLauncher\launcher.ps1` (установленная копия) |
| Настройки | `%LOCALAPPDATA%\ClaudeCodeLauncher\settings.json` |
| Лимиты, которые показывает лаунчер | `%LOCALAPPDATA%\ClaudeCodeLauncher\usage.json` (пишет мод `usage-mod`) |
| Мод `usage-mod` (плагин Claude Code): пишет модель и лимиты в usage.json | `%LOCALAPPDATA%\ClaudeCodeLauncher\usage-mod\` |
| Мод `limits-bar`: строка с моделью, контекстом и лимитами над полем ввода | `%LOCALAPPDATA%\ClaudeCodeLauncher\limits-bar\` |
| Скомпилированная поддержка мыши (кэш, можно удалить, пересоберётся) | `%LOCALAPPDATA%\ClaudeCodeLauncherin\ccl-input-*.dll` |
| Временные файлы обновлений и скиллов | `%LOCALAPPDATA%\ClaudeCodeLauncher	mp\` |
| Скиллы, поставленные из лаунчера | `~/.claude/skills/<имя>`, список в поле `skills` в `settings.json` |
| Источник обновлений и каталога скиллов | `$DefaultSource` в начале `launcher.ps1` или поле `updateSource` в `settings.json`; в корне репозитория лежит `manifest.json` |
| Профиль Windows Terminal «Claude Code Launcher» и цветовая схема «Claude Launcher» | `%LOCALAPPDATA%\Microsoft\Windows Terminal\Fragments\ClaudeCodeLauncher\launcher.json` |
| Ярлыки «Claude Code Launcher.lnk» | рабочий стол и меню «Пуск» → `wt.exe --size C,R --pos X,Y -p "Claude Code Launcher"` |

- Моды подключаются **только** к сессиям, которые запускает лаунчер: флагом `claude --plugin-dir <папка мода>`. Язык строки лимитов передаётся переменной окружения `CCL_LANG`.
- Ключи скрипта: `-Install` (скопировать себя и моды, создать профиль и ярлыки), `-Uninstall`, `-Quiet` (без вопросов).
- Список проектов и сессий лаунчер берёт из `~/.claude/projects/*/*.jsonl` (поле `cwd` и первые сообщения). Он их только читает.

## Как найти поломку

0. Сначала посмотри, что говорит сам лаунчер: «Настройки → Проверка компонентов» (пункт «Скопировать отчёт» кладёт отчёт в буфер обмена). Если лаунчер падает, текст ошибки остаётся на экране и копируется в буфер обмена.
1. Проверь окружение: `claude --version`, есть ли `wt.exe` (Windows Terminal), `git --version`. Если Claude Code не установлен, скажи об этом и предложи официальный установщик: `irm https://claude.ai/install.ps1 | iex`.
2. Проверь синтаксис скрипта:
   ```powershell
   $t=$null;$e=$null;[System.Management.Automation.Language.Parser]::ParseFile("$env:LOCALAPPDATA\ClaudeCodeLauncher\launcher.ps1",[ref]$t,[ref]$e) | Out-Null; $e
   ```
3. Запусти лаунчер так, чтобы окно с ошибкой не закрылось, и попроси пользователя прислать скриншот или текст ошибки:
   ```
   wt.exe powershell -NoExit -NoProfile -ExecutionPolicy Bypass -File "%LOCALAPPDATA%\ClaudeCodeLauncher\launcher.ps1"
   ```
4. Повреждённые настройки: переименуй `settings.json` в `settings.bak.json`. Лаунчер создаст новый и покажет экран первичной настройки.
5. Моды: `claude plugin validate "%LOCALAPPDATA%\ClaudeCodeLauncher\usage-mod"` и то же для `limits-bar`. Если строка лимитов в Claude не появляется, запусти `claude --debug --plugin-dir <папка мода>` и посмотри строки с именем мода.
6. Лимиты пусты: они приходят только при входе по подписке (Pro/Max) и только после первого ответа Claude в сессии, запущенной из лаунчера.
7. Ярлык ничего не открывает: проверь, что файл профиля на месте и это валидный JSON, и что `wt.exe` существует. Проще всего переустановить:
   ```
   powershell -NoProfile -ExecutionPolicy Bypass -File "<папка с дистрибутивом>\launcher.ps1" -Install
   ```
   Если дистрибутива нет, подойдёт установленная копия: `-Install` перезапишет профиль и ярлыки.
8. Окно слишком большое или маленькое: «Настройки → Подогнать окно под экран» или переустановка.

## Правила правки launcher.ps1 (на этом уже ломалось)

- Сохраняй файл в **UTF-8 с BOM**. Без BOM Windows PowerShell 5.1 портит кириллицу и падает.
- В PowerShell имена переменных **не различают регистр**: `$s` и `$S`, `$r` и `$R`, `$first` и `$First` это одна и та же переменная, а вложенные блоки видят переменные вызывающей функции. Не создавай локальных переменных с именами глобальных: `$Cfg`, `$G`, `$R`, `$E`, `$W`, `$H`, `$Clay`, `$Ivory`, `$Dim`, `$Muted`.
- Не используй типографские апострофы и кавычки `’ ‘` внутри строк в одинарных кавычках: PowerShell считает их кавычками.
- `[Console]::WindowWidth` падает без окна консоли: используй функцию `Console-Width`.
- После правки проверь синтаксис (шаг 2) и запусти лаунчер (шаг 3).
- Перед запуском Claude и при выходе режим ввода консоли возвращается функцией `Input-Restore` (мышь включается только на время меню). Новые места, где запускается внешняя программа или читается строка (`ReadLine`), тоже должны вызывать `Input-Restore`.
- Обновление ставит файлы из `manifest.json` рядом с запущенным скриптом (`$PSScriptRoot`), сверяя SHA-256. Если меняешь файлы в репозитории, пересобери манифест: `tools\Make-Manifest.ps1`.
- Если правишь установленную копию, предложи внести ту же правку в `launcher.ps1` дистрибутива, иначе переустановка её затрёт.

В конце коротко объясни пользователю, что было сломано и что ты сделал.
